# PR Gate (v0.7.2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every pull request is gated by linting, type checking and the full test suite, enforced by GitHub branch protection so a red check disables the merge button.

**Architecture:** Add `lint` and `typecheck` jobs to the existing `ci.yml`, alongside the four jobs already there (`cpp`, `python`, `ui`, `coverage`). Linters are configured to match this codebase's actual style rather than to impose a stock one — the measurement below is why. Branch protection on `main` then requires the five blocking checks.

**Tech Stack:** ruff, mypy, clang-format (via its pip wheel), Node's built-in `--check`, GitHub Actions, `gh` CLI.

Version: **0.7.2**. No git tag, no GitHub release. Merged and pushed to `main`.

## Measurement that shaped this plan

Run before writing it, on the v0.7.1 tree:

- **ruff, default rules: 62 findings — 7 are defects.** 47 are E701/E702 (deliberately paired setup lines such as `hub_dir.mkdir(); cache.mkdir()`), 8 are E401 (`import pytest, helpmate`). The genuine ones: 4 unused imports (F401), 2 ambiguous `l` names (E741), 1 lambda assignment (E731).
- **`ruff format` would rewrite 1101 lines across 23 files.** Not adopted; see Task 1.
- **mypy: 2 findings**, both benign — an `Optional` narrowing mypy cannot see, and a `# type: ignore` naming the wrong error code.
- **clang-format: 3715 replacements across 43 files totalling 4365 lines** under stock Google style; **971 at best** after tuning indent width, column limit, access-modifier offset, short-form allowances and pointer alignment. Roughly one line in five, in the most carefully reviewed code in the project. Whole-file enforcement is therefore rejected in favour of changed-lines-only; see Task 2.

The distinction this plan rests on: **selecting a ruleset** ("E702 does not apply to this project") is a permanent, honest configuration decision. **Baselining** ("E702 applies, but the existing 47 violations are grandfathered") teaches everyone to ignore a rule. This plan does the first and never the second — there is no ignore-list of existing findings anywhere in it.

## Global Constraints

- **Max 4 cores.** Prefix every build/test command with `taskset -c 0-3`.
- **Never touch `~/tb`.** Use `$(mktemp -d)` for scratch tables.
- **Never run bare `./build/helpmate_tests`** — always `"~[slow]"`.
- **Prefix any `pip install` that may build C++ with `GIT_CONFIG_GLOBAL=/dev/null`** and use `CC=gcc-13 CXX=g++-13`. Without the prefix, this machine's gitconfig HTTPS→SSH rewrite makes FetchContent hang on an invisible passphrase dialog: no error, no timeout.
- **Never wait on a process with `until ! pgrep -f "<pattern>"`** — `pgrep -f` matches the waiting shell's own command line and the loop never exits.
- **No new npm dependency.** The dashboard is deliberately build-step-free; ESLint would require `node_modules` and is out of scope. `node --check` is the JS gate.
- **No ignore-list of pre-existing findings.** Every configured rule must pass on the whole tree from the first commit.
- ctest must still total exactly **117**; `helpmate_tests "~[slow]"` must report **86**.
- Commit trailer, exactly: `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`

**Branch.** All tasks land on `v0.7.2-pr-gate`, cut from `main`:

```bash
git checkout main && git pull && git checkout -b v0.7.2-pr-gate
```

### Task 2: C++ formatting, enforced on changed lines only

**Files:**
- Create: `.clang-format`
- Modify: `Makefile`, `docs/BUILD.md`

**Interfaces:**
- Consumes: nothing.
- Produces: `make format-check`, which exits non-zero when lines changed relative to the merge base are misformatted. Task 3 wires it into CI.

- [ ] **Step 1: Write a config tuned to the existing style**

Whole-file enforcement is rejected: stock Google style makes 3715 replacements across 4365 lines of C++, and the best tuning found still makes 971. The config below is that best tuning — it minimises disagreement with existing code, so the changed-lines check rarely fights the author.

Create `.clang-format`:

```yaml
# Tuned to the code that already exists rather than to a stock style. Measured
# on the v0.7.1 tree: stock Google makes 3715 replacements across 43 files
# (4365 lines total); this config makes 971. Enforcement is therefore on
# CHANGED LINES ONLY (see `make format-check`) -- a PR must format what it
# touches, and the rest of the tree is never rewritten. The codebase converges
# as it is edited instead of in one unreviewable commit.
BasedOnStyle: Google
ColumnLimit: 110
IndentWidth: 4
AccessModifierOffset: -4
AllowShortFunctionsOnASingleLine: All
AllowShortIfStatementsOnASingleLine: AllIfsAndElse
AllowShortBlocksOnASingleLine: Always
AllowShortLoopsOnASingleLine: true
DerivePointerAlignment: false
PointerAlignment: Left
```

- [ ] **Step 2: Add the changed-lines check**

`git-clang-format` ships with the clang-format pip wheel. Add to the Makefile:

```make
# Formatting is enforced on the lines a change touches, not on the whole tree:
# reformatting all 4365 lines of existing C++ would be one unreviewable commit
# over the most carefully reviewed code in the project. BASE defaults to the
# merge base with main, which is what CI uses.
BASE ?= $(shell git merge-base origin/main HEAD 2>/dev/null || echo HEAD~1)
format-check:
	git clang-format --diff $(BASE) -- '*.cpp' '*.h' | tee /tmp/hm-fmt.diff
	@test ! -s /tmp/hm-fmt.diff || { echo "C++ formatting: run 'make format' and commit"; exit 1; }
format:
	git clang-format $(BASE) -- '*.cpp' '*.h'
```

Add both to `.PHONY`.

- [ ] **Step 3: Prove the check works, in both directions**

It must pass on an unmodified tree:

```bash
taskset -c 0-3 make format-check
```
Expected: no diff, exit 0.

It must fail on a badly formatted change. Introduce one deliberately, check, then revert:

```bash
printf '\nint    badly_formatted_probe(  int x ){return x  ;}\n' >> src/core/probe/tablebase.cpp
taskset -c 0-3 make format-check; echo "exit=$?"      # expect non-zero, diff shown
git checkout src/core/probe/tablebase.cpp
taskset -c 0-3 make format-check; echo "exit=$?"      # expect 0
git diff --stat                                        # must be empty
```

Report both outputs. A check that cannot fail is not a check.

- [ ] **Step 4: Document it and commit**

In `docs/BUILD.md`, next to the test targets, add a short section: `make format-check` (what CI runs), `make format` (fix it), and one sentence on why enforcement is changed-lines-only, citing the 3715-vs-971 measurement so nobody "fixes" it later by reformatting everything.

```bash
git add -A && git commit -m "build: clang-format on changed lines only

Config tuned to the existing code (971 replacements vs stock Google's 3715

Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>"
```

### Task 3: CI jobs for lint, typecheck and format

**Files:**
- Modify: `.github/workflows/ci.yml`

**Interfaces:**
- Consumes: `make lint`, `make typecheck`, `make format-check` from Tasks 1-2.
- Produces: five job names that Task 4 marks as required checks. Their exact names matter — Task 4 references them verbatim: `Lint (ruff, node --check)`, `Type check (mypy)`, `C++ format (changed lines)`, and the existing `C++ build, fast tests, CLI smoke`, `Python bindings`, `Dashboard (browser tests)`.

- [ ] **Step 1: Add the three new jobs**

Insert before the existing `coverage` job. These are fast (no C++ build), so they fail a PR in under a minute rather than after the ten-minute compile:

```yaml
  lint:
    name: Lint (ruff, node --check)
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - name: Install ruff
        run: python -m pip install ruff
      - name: Ruff
        run: ruff check .
      # No ESLint: the dashboard is deliberately npm-free with no build step.
      # `node --check` parses every module without installing anything.
      - name: JS syntax
        run: node --check $(git ls-files 'src/packages/web/helpmate_web/static/js/*.js' 'src/packages/web/helpmate_web/static/js/lib/*.js')

  typecheck:
    name: Type check (mypy)
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      # mypy needs the server's own dependencies to resolve its imports, but
      # NOT the compiled `helpmate` extension -- ignore_missing_imports covers
      # that, and installing it would mean a ten-minute C++ build for a
      # type-check job.
      - name: Install typing dependencies
        run: python -m pip install mypy fastapi uvicorn huggingface_hub
      - name: mypy
        run: python -m mypy

  cppformat:
    name: C++ format (changed lines)
    runs-on: ubuntu-24.04
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0        # git-clang-format needs the merge base
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - name: Install clang-format
        run: python -m pip install clang-format
      - name: Check formatting of changed lines
        run: |
          BASE="$(git merge-base origin/${{ github.base_ref || 'main' }} HEAD)"
          make format-check BASE="$BASE"
```

- [ ] **Step 2: Guard against the stale-binary class of failure**

v0.7.1 shipped a bug where `ctest` passed while `./build/helpmate` did not exist, because a pre-split build had left a stale binary at the old path locally. CI caught it only because a fresh checkout has no stale copies. Make that guarantee explicit rather than incidental — add to the `cpp` job, immediately after the build step:

```yaml
      # The v0.7.1 CMake split moved executables into subdirectories while
      # ctest kept passing, because ctest resolves target paths itself. Locally
      # a stale pre-split binary at the old path hid it for five tasks. Assert
      # the documented paths exist, so a future layout change fails loudly here
      # instead of silently everywhere else.
      - name: Binaries are at their documented paths
        run: |
          test -x build/helpmate       || { echo "build/helpmate missing"; exit 1; }
          test -x build/helpmate_tests || { echo "build/helpmate_tests missing"; exit 1; }
```

### Task 4: Version-tag guard and branch protection

**Files:**

- Consumes: the job names from Task 3.

- [ ] **Step 1: Guard the release tag against VERSION**

The v0.7.1 whole-branch review found the one remaining place the version can drift: nothing checks that a pushed `v*` tag agrees with the `VERSION` file, so a `v0.7.3` tag could publish a tarball whose binary reports `0.7.2`. Add as the first step of the release job, after checkout:

```yaml
      - name: Tag must match VERSION
        run: |
          TAG="${GITHUB_REF_NAME#v}"
          FILE="$(cat VERSION)"
          test "$TAG" = "$FILE" || {
            echo "tag $GITHUB_REF_NAME does not match VERSION ($FILE)"; exit 1; }
```

Read `.github/workflows/release.yml` first and place it consistently with the existing steps; if the workflow's checkout step is not first, adapt rather than assume.
